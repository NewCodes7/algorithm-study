### 다이나믹 프로그래밍 (동적 계획법)
- 의미: 메모리를 적절히 사용하여 수행 시간 효율성을 비약적으로 향상시키는 방법
- 원리: 이미 계산된 결과(작은 문제)를 별도의 메모리 영역에 저장하여 필요할 때 재활용함.
- 조건: 큰 문제를 동일한 작은 문제로 나누어 풀 수 있는가?
  - 최적 부분 구조: 큰 문제를 작은 문제로 나눌 수 있으며 작은 문제의 답을 모아서 큰 문제를 해결
  - 중복되는 부분 문제: 동일한 작은 문제를 반복적으로 해결
- 방식
  - 탑다운(하향식)
    - 메모이제이션
      - 의미: 한 번 계산한 결과를 메모리 공간에 메모하는 기법
      - 다이나믹 프로그래밍을 구현하는 방법 중의 하나
      - 값을 기록해 놓는다는 점에서 캐싱(Caching)이라고도 함.
  - 보텀업(상향식) !!
    - 다이나믹 프로그래밍의 전형적인 형태
    - DP 테이블: 결과 저장용 리스트
- 문제 접근 방법
  - 가장 먼저 그리기, 구현, 완전 탐색 등으로 아이디어 생각해보기
    - 다른 알고리즘이 떠오르지 않는다면 다이나믹 프로그래밍 고려
  - 우선 재귀함수로 풀이 시도(탑다운). 동일한 작은 문제가 발견되면 리팩토링.

### 🔥 LIS(Longest Increasing Subsequence) 최장 증가 부분 수열
- 의미: 특정 수열에서 **몇 개의 원소를 선택해** 오름차순으로 정렬된 가장 긴 부분 수열을 찾는 알고리즘 
- 풀이 종류
  - dp
  - 이진탐색
- 🔥 원리: 각 원소의 지위, 랭크를 매기는 작업을 **순차적으로** 선행함. 
  - 이전 index && 자신보다 한 단계 더 작은
  - 🔥🔥 dp라고 해서 이중반복문 안 되는 거 아니다!! rank 매기는 작업은 한 번 순회로는 안 돼!
- 🔥 결과: dp 배열에서 가장 큰 값이 최장 증가 부분 수열의 길이임.
- 🔥 소스코드
```java

//dp 배열 1로 초기화 or 마지막에 1 더해주면 됨.

    for (int i = 1; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (list.get(j) < list.get(i)) { // dp자리 아니라 수열 자리다!! 조심
                dp[i] = Math.max(dp[i], dp[j] + 1);
            }
        }
    }
```

### 🔥 [완전범죄 (프로그래머스 389480)](../프로그래머스/2/389480. 완전범죄/README.md) — 상태 압축 → DP (2026-10-15)
- **핵심 사고 질문:** “모든 경우의 수를 기억해야 할까? 아니면 특정 조건이 같은 경우들 중 최적의 값 하나만 기억하면 될까?”
- **완전탐색 → 지배 관계/중복 상태 파악 → 상태 압축 가능 → DP 검토.** 선택지마다 갈라지는 `2^40`가지 경로를 전부 저장할 필요가 없는지 먼저 확인.
- **이번 문제의 상태 정의:** `dp[b] = B 흔적이 정확히 b일 때 가능한 최소 A 흔적`. B가 같으면 A 흔적이 더 큰 상태는 이후 어떤 선택에서도 유리하지 않으므로 버려도 됨. A+B 합만 같은 두 상태는 중복이 아님.
- **DP가 되는 추가 근거:** 과거의 세부 경로 대신 지금 남긴 `b`와 최소 `A`만으로 다음 물건의 두 선택을 모두 계산할 수 있음. 상태 압축을 찾은 뒤 **상태의 충분성과 전이 가능성**까지 확인하기.
- **단계 구분:** 물건 하나를 한 번만 훔치므로 이전 `dp`를 읽어 `newDp`에 쓰고, 완성 후 교체. `< n` / `< m` 경계도 확인.
- **복잡도:** `O(물건 수 × m)`, 공간 `O(m)`. m의 상한이 120인 점을 활용.
- **복습:** [최종 Java 원본](../프로그래머스/2/389480. 완전범죄/완전범죄.java) · [상세 피드백](../프로그래머스/2/389480. 완전범죄/FEEDBACK_2026-10-15.md) · [재풀이 목록](../RETRY_PROBLEMS.md)


### 🔥 [코딩 테스트 공부 (프로그래머스 118668)](../프로그래머스/3/118668. 코딩 테스트 공부/README.md) — 다익스트라 → 2차원 DP (2026-10-22)

- **DP를 떠올리는 질문:** 앞으로의 선택을 결정하는 정보는 무엇인가? 그 정보가 같다면 어떤 경로 하나만 남겨도 되는가? 어떤 순서로 계산할 수 있는가?
- **상태와 값 구분:** `dp[a][c] = 알고력 a, 코딩력 c까지의 최소 시간`. 같은 능력치면 이후 가능한 행동·비용이 같으므로 느린 경로는 버릴 수 있음.
- **점화식:** 현재 상태에서 공부·풀 수 있는 모든 문제를 시도하고 `dp[next] = Math.min(dp[next], dp[current] + 비용)`으로 전달. 당장 좋은 행동 하나를 고르는 것이 아님.
- **순회 순서:** 능력치가 감소하지 않으므로 알고력·코딩력 오름차순으로 처리 가능. 자기 자신으로 돌아오는 양의 비용 행동은 개선하지 못함. 현재 칸으로 들어올 유효한 전이들은 이미 반영되어 있음.
- **목표 초과 상태 합치기:** 요구 능력치의 최댓값을 넘으면 미래 선택이 같음. 보상뿐 아니라 **초기 능력치도** `Math.min()`으로 제한하기!
- **상태 정의와 처리 방식은 별개:** 같은 능력치 상태를 오름차순 DP 또는 다익스트라로 처리 가능. 이번 문제는 순회 근거가 있어 큐 없이 해결됨.
- **다익스트라 조건 구분:** 꺼낼 때 확정하면 `>=`를 건너뛰고 시작값은 `INF`. 넣기 전에 기록하면 `>`만 건너뛰고 시작값은 `0`. 두 방식을 섞지 않기.
- **배열·초기화:** 최대 `151 × 151` 상태. 원본 `+2`도 맞지만 개선안은 `+1`과 공부 경계 검사. 이번 순회 범위는 공부만으로 모두 도달하므로 `INF + 비용` 오버플로가 발생하지 않음.
- **복잡도:** 목표 상태 수 `V`, 문제 수 `P`일 때 DP `O(VP)` 시간, `O(V)` 공간.
- **복습:** [사용자 DP 원본](../프로그래머스/3/118668. 코딩 테스트 공부/코딩 테스트 공부.java) · [사용자 다익스트라 원본](../프로그래머스/3/118668. 코딩 테스트 공부/DIJKSTRA_2026-10-22.java) · [학습 총정리](../프로그래머스/3/118668. 코딩 테스트 공부/FEEDBACK_2026-10-22.md)
