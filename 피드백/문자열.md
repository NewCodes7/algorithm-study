### [문자열 압축](프로그래머스/2/60057. 문자열 압축) x 2
- 메서드 분리의 필요성! (레벨2이상은 메서드 분리하면서 풀어야 할 듯) (급하게 하지마)
    - 리팩토링 용이함.
    - 구현하는 동안 가독성 올라감.
- 문자열 비교는 _equals_ !!!
- 🔥 subString (x) substring (o)
  - str1.substring(int startIndex) // startIndex부터 끝까지의 문자열을 리턴
  - str2.substring(int startIndex, int endIndex) // startIndex(포함)부터 endIndex(불포함)까지의 문자열을 리턴

- 들여쓰기 설계할 때, 조금만 더 구체적으로 하자. 비교를 한다면 어떤 것과 비교를 하는지 구체적으로.
- substring(start, end) // end는 문자열의 길이가 나올 수 있다!


#### 2026-09-19 재풀이 피드백
- [상세 비교·개선 코드·검증 결과](../프로그래머스/2/60057. 문자열 압축/FEEDBACK_2026-09-19.md)
- 현재 최종 풀이: 완전탐색 + 연속 토큰 묶기. 시간 O(n²), 공간 O(n). Java 17 로컬 검증 2,264건에서 정답과 일치함.
- 과거 기록: 2024-01-05 메서드 분리·토큰 순회, 2024-02-14 substring·n/2 탐색, 2026-03-04 후보 안에서 StringBuilder 생성.
- 이번에 개선한 점: 첫 토큰을 먼저 설정해 비교 시작을 명확히 함. char[]를 후보마다 다시 만들지 않음.
- 이번 디버깅의 핵심: 완성되지 않은 마지막 토큰 누락, 후보 사이 sb 초기화 누락, delete 끝 인덱스 혼동.
- delete(start, end)는 [start, end) 삭제. delete(0, length-1)은 마지막 글자를 남김. 전체 초기화는 setLength(0).
- 후보 하나에서만 쓰는 변수는 후보의 for문 몸체나 별도 메서드 안에서 생성하기. 초기화 누락 자체가 불가능한 범위로 제한하기.
- 마지막에는 before/count의 미확정 묶음과 sb의 짧은 나머지가 각각 남는다는 점을 구분하기.
- substring(start, Math.min(start + size, n))으로 토큰 단위 순회하면 짧은 나머지도 같은 흐름으로 처리 가능함.
- answer=n으로 시작하고 size≤n/2까지만 검사 가능. n=1도 자연스럽게 처리됨.
- “메서드 분리하기/설계 꼼꼼히”를 행동으로 구체화: 반복 단위, 미확정 상태, 종료 후 처리, 변수 수명 네 가지를 코딩 전에 적기.

### [3진법 뒤집기](프로그래머스/Lv.1/68935. 3진법 뒤집기)

    ```java
    int a = 10;
    String b = Integer.toString(a, 3); // 10진수 -> n진수
    int c = Integer.parserInt(b, 3); // n진수 -> 10진수
    ```
- 🔥🔥 문자열 뒤집기 -> sb이용!! 
    ```java
    String s = new StringBuilder(str).reverse().toString(); // append 써도 됨.
    ```
