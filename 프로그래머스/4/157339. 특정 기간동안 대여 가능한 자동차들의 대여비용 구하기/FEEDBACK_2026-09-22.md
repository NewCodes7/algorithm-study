# 157339. 특정 기간동안 대여 가능한 자동차들의 대여비용 구하기

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/157339
- 풀이 시간: 13:26~13:43, 17분
- 환경: MySQL
- 정리 범위: 이번 대화에서 작성한 개선 SQL과 피드백
- 검증 범위: 쿼리와 설명을 검토했으며 MySQL 실행 및 온라인 채점은 별도로 수행하지 않음.

## 개선한 풀이

사용자가 개선한 CTE와 FLOOR 구조를 유지하고, 문자열 따옴표와 기간 겹침 조건을 정리했다.

```sql
WITH RENTAL_FEES AS (
    SELECT
        A.CAR_ID,
        A.CAR_TYPE,
        FLOOR(A.DAILY_FEE * 30 * (100 - C.DISCOUNT_RATE) / 100) AS FEE
    FROM CAR_RENTAL_COMPANY_CAR A
    JOIN CAR_RENTAL_COMPANY_DISCOUNT_PLAN C
        ON A.CAR_TYPE = C.CAR_TYPE
    WHERE A.CAR_ID NOT IN (
        SELECT H.CAR_ID
        FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY H
        WHERE H.START_DATE <= '2022-11-30'
          AND H.END_DATE >= '2022-11-01'
    )
      AND A.CAR_TYPE IN ('SUV', '세단')
      AND C.DURATION_TYPE = '30일 이상'
)
SELECT CAR_ID, CAR_TYPE, FEE
FROM RENTAL_FEES
WHERE FEE >= 500000 AND FEE < 2000000
ORDER BY FEE DESC, CAR_TYPE ASC, CAR_ID DESC;
```

## 풀이 피드백

### 1. 조인을 못 쓰는 문제가 아니라 판단 단위가 다른 문제

안 겹치는 이력이 한 건 존재하는 것과, 겹치는 이력이 한 건도 없는 것은 다르다.
같은 차량에 10/01~10/05 기록과 11/10~11/15 기록이 있다면, 이력을 조인해서 안 겹치는 행만 남기는 방식은 10월 기록을 남긴다. 하지만 이 차량은 11월 전체 대여가 불가능하다.

올바른 회고: "기간과 겹치는 이력이 하나라도 있는 차량을 제외해야 하므로 NOT IN으로 해당 ID를 제외했다. NOT EXISTS나 LEFT JOIN 방식도 가능하다."

LEFT JOIN으로 구현하려면 겹침 조건을 ON에 넣고 매칭되지 않은 차량을 고른다.

```sql
FROM CAR_RENTAL_COMPANY_CAR A
LEFT JOIN CAR_RENTAL_COMPANY_RENTAL_HISTORY H
    ON H.CAR_ID = A.CAR_ID
   AND H.START_DATE <= '2022-11-30'
   AND H.END_DATE >= '2022-11-01'
WHERE H.HISTORY_ID IS NULL
```

이 코드는 이력 제외 부분만 표현한 예시다. 할인 정책 조인과 차종·금액 조건은 별도로 필요하다.

### 2. 기간 겹침 조건

```sql
NOT (END_DATE < '2022-11-01' OR START_DATE > '2022-11-30')
```

드모르간 법칙으로 다음과 같다.

```sql
START_DATE <= '2022-11-30' AND END_DATE >= '2022-11-01'
```

일반식: 내 시작일 <= 상대 종료일 AND 내 종료일 >= 상대 시작일.
경계일 당일에 종료하거나 시작해도 겹친다. 한 기간이 다른 기간을 완전히 포함해도 잡힌다.

### 3. 요금 계산과 CTE

- DAILY_FEE * 30 * (100 - DISCOUNT_RATE) / 100 계산식은 맞다.
- 같은 식을 SELECT와 WHERE에서 반복하지 않도록 CTE에서 계산한다.
- SELECT에서 정의한 별칭은 같은 쿼리 단계의 WHERE에서 바로 참조할 수 없으므로 바깥 쿼리에서 필터링한다.
- 정수 부분만 출력하라는 조건에 맞춰 FLOOR를 사용한다. 요금은 양수이므로 내림이 정수 부분 제거와 같다.
- 이번 문제의 금액 경계는 정수이므로 FLOOR를 적용한 후 필터링해도 포함 여부는 같다.
- DISTINCT는 선택한 모든 컬럼의 조합에 적용된다. DISTINCT(CAR_ID)는 CAR_ID만 중복 제거하는 함수가 아니다.
- 차종별 30일 이상 할인 정책이 하나씩 매칭되는 구조에서는 차량 행이 증식하지 않으므로 DISTINCT가 필요 없다.

## IN / EXISTS / NOT IN / NOT EXISTS

| 구문 | 판단 기준 | 의미 |
|---|---|---|
| IN | 값의 포함 여부 | 값이 목록에 있는가? |
| NOT IN | 값의 미포함 여부 | 값이 목록에 없는가? |
| EXISTS | 행의 존재 여부 | 조건을 만족하는 행이 하나라도 있는가? |
| NOT EXISTS | 행의 부재 여부 | 조건을 만족하는 행이 하나도 없는가? |

이번 풀이의 NOT IN은 아래 NOT EXISTS로 대체할 수 있다.

```sql
AND NOT EXISTS (
    SELECT 1
    FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY H
    WHERE H.CAR_ID = A.CAR_ID
      AND H.START_DATE <= '2022-11-30'
      AND H.END_DATE >= '2022-11-01'
)
```

- H.CAR_ID = A.CAR_ID는 현재 차량과 이력을 연결한다. 바깥 컬럼을 참조하므로 상관 서브쿼리다.
- 연결 조건을 빼면 어느 차량이든 겹치는 이력이 존재하는지만 판단한다.
- EXISTS는 SELECT 결과 값이 아니라 행 존재 여부를 확인한다. 이 예시에서 SELECT 1을 SELECT NULL로 바꿔도 동일하다.
- 이번 문제의 양쪽 CAR_ID는 NOT NULL이므로 NOT IN도 적절하다.
- EXISTS가 무조건 빠른 것은 아니다. 성능은 DB 최적화, 데이터, 인덱스와 실행 계획으로 판단한다.

## NULL과 3값 논리

NULL과 일반 비교 연산자(=, <>)로 비교하면 UNKNOWN이다. NULL = NULL도 UNKNOWN이다.
WHERE는 TRUE인 행만 남긴다. FALSE와 UNKNOWN은 모두 제외한다.

| 표현 | 결과 | WHERE 통과 |
|---|---|---|
| 3 IN (1, 3, NULL) | TRUE | O |
| 3 IN (1, 2, NULL) | UNKNOWN | X |
| 3 IN (1, 2) | FALSE | X |
| NULL IN (1, 2, NULL) | UNKNOWN | X |
| 3 NOT IN (1, 3, NULL) | FALSE | X |
| 3 NOT IN (1, 2, NULL) | UNKNOWN | X |

```sql
3 IN (1, 3, NULL)
-- 3 = 1 OR 3 = 3 OR 3 = NULL
-- FALSE OR TRUE OR UNKNOWN = TRUE

3 NOT IN (1, 2, NULL)
-- 3 <> 1 AND 3 <> 2 AND 3 <> NULL
-- TRUE AND TRUE AND UNKNOWN = UNKNOWN
```

NOT FALSE는 TRUE지만 NOT UNKNOWN은 UNKNOWN이다.

### 실제 문제가 되는 경우

1. IN (1, NULL)에 NULL인 행도 포함될 것으로 기대하는 경우: 실제로는 1만 조회된다.
2. NOT IN (1, NULL)에서 1 이외의 값을 남기려는 경우: 다른 값도 UNKNOWN이 되어 제외된다.

NULL인 행도 조회하려면 명시적으로 조건을 추가한다.

```sql
WHERE CAR_ID IN (1, 2) OR CAR_ID IS NULL
```

### NOT IN 서브쿼리에 NULL이 있을 수 있다면

서브쿼리 결과에서 NULL을 제거한다.

```sql
WHERE A.CAR_ID NOT IN (
    SELECT H.CAR_ID
    FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY H
    WHERE H.CAR_ID IS NOT NULL
      AND H.START_DATE <= '2022-11-30'
      AND H.END_DATE >= '2022-11-01'
)
```

바깥쪽 A.CAR_ID도 NULL일 수 있고 이를 포함하려면 A.CAR_ID IS NULL OR (...)를 사용한다.
NOT EXISTS의 등호 매칭은 안쪽 NULL 행을 매칭하지 않으므로 그 행 때문에 다른 차량까지 일괄 제외되지 않는다. 단, NULL끼리 같다고 판단하는 것은 아니다.

정확한 예외: 서브쿼리가 빈 집합이면 NULL IN (빈 집합)은 FALSE, NULL NOT IN (빈 집합)은 TRUE다. 바깥 값이 NULL이라고 항상 UNKNOWN인 것은 아니다.

## 다음 풀이에서 확인할 것

- 한 행의 조건인지, 해당 대상의 전체 기록에 대한 조건인지 구분한다.
- 기간 겹침은 시작일 <= 상대 종료일 AND 종료일 >= 상대 시작일로 표현한다.
- 정수 출력 조건과 금액 상한의 미만(<) 조건을 확인한다.
- DISTINCT를 붙이기 전에 조인으로 행이 증식하는 이유를 확인한다.
- NOT IN 사용 시 서브쿼리 결과의 NULL 가능성을 확인한다.

## 기존 저장소 풀이와 비교

기존 풀이는 대여 이력을 INNER JOIN한 뒤 GROUP BY로 차량을 묶었다. 이력이 없는 차량은 조인 단계에서 빠질 수 있다. 이번 풀이는 차량 테이블에서 출발하고 겹치는 이력만 제외하므로 이력이 없는 차량도 유지한다. 기존 ROUND는 반올림이므로 정수 부분만 출력하는 FLOOR로 변경했다. 이전 코드는 Git 이력에서 확인할 수 있다.
