# 301650. 특정 세대의 대장균 찾기

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/301650
- 풀이일: 2026-09-27
- 환경: MySQL
- 유형: SELF JOIN, 계층형 관계, CTE, SQL 키워드 충돌 디버깅

## 복습 요약

- 같은 테이블 안의 부모-자식 관계를 여러 단계 추적할 때 SELF JOIN을 연속해서 사용할 수 있다.
- 이번 풀이에서 A=3세대, B=2세대, C=1세대로 두고 부모 ID를 따라 올라간다.
- `C.PARENT_ID IS NULL`이 있어야 C가 반드시 1세대가 되므로 A가 정확히 3세대가 된다.
- `WITH SECOND AS (...)`는 프로그래머스에서 `Only SELECT statements are allowed` 오류가 발생했다.
- 프로그래머스가 CTE 자체를 지원하지 않는 것은 아니다. `SECOND`를 `SECOND_GEN`으로 바꾸면 같은 CTE 구조가 실행됐다.
- MySQL 8.0에서 `SECOND`는 시간 단위에 사용되는 SQL 키워드다. 예약어(reserved word)는 아니어서 MySQL 자체에서는 식별자로 사용할 수 있지만, 코딩테스트 플랫폼의 사전 SQL 검증기와 충돌할 수 있으므로 피하는 편이 안전하다.
- CTE·별칭에는 `SECOND_GEN`, `GEN2`, `SECOND_GENERATION`처럼 SQL 의미와 겹치지 않는 이름을 사용한다.

## 최종 풀이

```sql
SELECT A.ID
FROM ECOLI_DATA A 
JOIN ECOLI_DATA B ON A.PARENT_ID = B.ID
JOIN ECOLI_DATA C ON B.PARENT_ID = C.ID
WHERE C.PARENT_ID IS NULL 
ORDER BY A.ID;
```

## 풀이 구조

관계를 다음처럼 본다.

```text
C (1세대)
↓
B (2세대)
↓
A (3세대)
```

첫 번째 JOIN:

```sql
JOIN ECOLI_DATA B ON A.PARENT_ID = B.ID
```

A의 부모를 B로 연결한다.

두 번째 JOIN:

```sql
JOIN ECOLI_DATA C ON B.PARENT_ID = C.ID
```

B의 부모를 C로 연결한다.

마지막 조건:

```sql
WHERE C.PARENT_ID IS NULL
```

C가 최초 개체, 즉 1세대임을 보장한다. 따라서 C의 자식 B는 2세대, B의 자식 A는 정확히 3세대다.

## 왜 C.PARENT_ID IS NULL이 필요한가

아래 두 JOIN만 있으면:

```text
C → B → A
```

라는 연속된 세 개의 관계만 확인한다.

예를 들어 실제 계보가:

```text
1세대 → 2세대 → 3세대 → 4세대
```

라면 2세대 → 3세대 → 4세대도 JOIN 조건을 만족한다. 그러면 4세대까지 결과에 포함될 수 있다.

따라서 가장 위의 C가 반드시 1세대인지:

```sql
C.PARENT_ID IS NULL
```

로 확인해야 한다.

## 처음 시도한 CTE

```sql
WITH SECOND AS (
    SELECT A.ID
    FROM ECOLI_DATA A
    JOIN ECOLI_DATA B ON A.PARENT_ID = B.ID
    WHERE B.PARENT_ID IS NULL
)

SELECT A.ID
FROM ECOLI_DATA A
JOIN SECOND B ON A.PARENT_ID = B.ID
ORDER BY A.ID;
```

논리는 맞다.

CTE 안에서는:

- B가 `PARENT_ID IS NULL` → B는 1세대
- A의 `PARENT_ID = B.ID` → A는 2세대
- 따라서 CTE는 2세대 ID 목록

바깥 쿼리에서는 그 2세대 ID를 부모로 가지는 행을 찾아 3세대를 구한다.

하지만 프로그래머스 실행기에서 다음 오류가 발생했다.

```text
Only SELECT statements are allowed
```

## 원인 확인

처음에는 프로그래머스가 `WITH`로 시작하는 문장을 SELECT로 인정하지 않는 문제처럼 보였다. 그러나 프로그래머스에는 MySQL CTE를 사용한 정상 풀이가 존재하며, 실제로 CTE 이름만 바꾸자 실행됐다.

문제가 된 이름:

```sql
WITH SECOND AS (...)
```

동작한 이름:

```sql
WITH SECOND_GEN AS (...)
```

MySQL에서 `SECOND`는 다음처럼 시간 단위로 사용되는 키워드다.

```sql
INTERVAL 10 SECOND
```

MySQL 8.0 공식 키워드 목록에서 `SECOND`는 키워드지만 예약어 표시 `(R)`는 없다. 따라서 MySQL 엔진 자체에서 식별자로 쓰는 것이 원칙적으로 금지된 단어는 아니다.

이번 현상은 프로그래머스가 MySQL에 전달하기 전에 수행하는 SQL 검사/파싱 단계에서 `SECOND`를 특별하게 해석한 것으로 추정된다. 프로그래머스 내부 검증기의 정확한 구현은 공개되어 있지 않으므로 이 부분은 관찰 결과를 바탕으로 한 추정이다.

## 해결한 CTE 버전

```sql
WITH SECOND_GEN AS (
    SELECT A.ID
    FROM ECOLI_DATA A
    JOIN ECOLI_DATA B ON A.PARENT_ID = B.ID
    WHERE B.PARENT_ID IS NULL
)

SELECT A.ID
FROM ECOLI_DATA A
JOIN SECOND_GEN B ON A.PARENT_ID = B.ID
ORDER BY A.ID;
```

## 코테에서 가져갈 점

- SQL 오류가 뜨면 먼저 쿼리 로직 오류와 실행 환경의 파싱/검증 오류를 분리해서 생각한다.
- `WITH` 자체가 안 된다고 바로 결론 내리지 말고 최소 쿼리나 CTE 이름 변경으로 원인을 좁힌다.
- 테이블·CTE·alias 이름은 SQL 키워드와 겹치지 않게 짓는다.
- 특히 `SECOND`, `ORDER`, `GROUP`, `RANK`, `ROWS`, `INTERVAL`처럼 SQL에서 의미가 있는 단어는 피하는 습관을 들인다.
- 고정된 세대 수를 찾는 문제는 SELF JOIN이 간결하다. 세대 수가 가변적이면 재귀 CTE가 더 적합할 수 있다.
