## 풀이 중 발견한 핵심

처음에는 `GROUP BY FISH_TYPE`과 `MAX(LENGTH)`만으로 가장 긴 물고기의 `ID`도 구할 수 있다고 생각했다. 하지만 `MAX(LENGTH)`는 종류별 **최대 길이 값**을 반환할 뿐, 같은 SELECT에 적은 `ID`를 그 최대 길이의 행에서 가져온다는 보장은 없다. 이 점을 스스로 발견하고, 집계 결과를 원본 `FISH_INFO`에 다시 조인하는 서브쿼리 풀이로 바꿨다.

예를 들어 한 종류에 `(ID=11, LENGTH=20)`, `(ID=12, LENGTH=30)`이 있으면 필요한 결과는 `ID=12, LENGTH=30`이다. 다음 쿼리의 `ID`는 `MAX(LENGTH)`와 연결되지 않는다.

```sql
SELECT FISH_TYPE, ID, MAX(LENGTH)
FROM FISH_INFO
GROUP BY FISH_TYPE;
```

`ONLY_FULL_GROUP_BY`가 적용된 MySQL에서는 집계되지 않고 그룹 기준으로 결정되지 않는 `ID` 때문에 오류가 날 수 있다. 해당 검사가 꺼진 환경에서도 어느 행의 `ID`가 선택될지 보장되지 않는다. `ID`까지 `GROUP BY`에 넣으면 이번에는 종류마다 한 행만 남기는 목적이 깨진다.

## 이번에 작성한 원본 쿼리

```sql
SELECT A.ID, B.FISH_NAME, B.LENGTH
FROM FISH_INFO A JOIN (SELECT A.FISH_TYPE, B.FISH_NAME, MAX(A.LENGTH) AS LENGTH
                       FROM FISH_INFO A JOIN FISH_NAME_INFO B ON A.FISH_TYPE = B.FISH_TYPE
                       GROUP BY A.FISH_TYPE
                     ) B ON A.FISH_TYPE = B.FISH_TYPE AND A.LENGTH = B.LENGTH
ORDER BY A.ID
```

## 피드백

1. 종류별 최대 길이를 계산하고, 원본 행에 `FISH_TYPE`과 `LENGTH`를 함께 비교해 조인한 판단이 정확하다. 종류가 다른 두 물고기의 최대 길이가 같을 수도 있으므로 두 조건이 모두 필요하다.
2. 문제는 종류별 최대 길이의 물고기가 정확히 한 마리라고 보장한다. 다른 문제에서 공동 1등이 가능하면 이 조인은 동률인 원본 행을 모두 반환한다. 한 행만 원한다면 별도의 동률 처리 규칙이 필요하다.
3. `FISH_NAME_INFO`는 최대 길이를 구한 뒤 조인해도 된다. 집계 대상이 `FISH_INFO`로 명확해지고, `B.FISH_NAME`을 `GROUP BY` 없이 선택하는 문제도 피할 수 있다. 원본 쿼리가 `ONLY_FULL_GROUP_BY`에서 허용되는지는 실제 스키마가 `FISH_TYPE` → `FISH_NAME`의 함수 종속성을 보장하고 DB가 이를 인식하는지에 달렸다.
4. `MAX(LENGTH)`는 `NULL`을 무시하며, 문제는 길이가 `NULL`인 물고기만 있는 종류가 없다고 보장한다. 별도의 `NULL` 치환은 필요 없다.

## 복습할 패턴

1. 최종 결과가 집계 값인지, 그 값을 가진 **원본 행의 정보**인지 확인한다.
2. `GROUP BY`로 종류별 최대 길이를 구한다.
3. `(FISH_TYPE, LENGTH)`로 원본 행을 다시 찾아 `ID`를 얻는다.
4. 이름을 조인하고 `ID` 오름차순으로 정렬한다.

이 피드백의 SQL은 문제 조건에 맞춰 논리적으로 검토했으며 온라인 채점 실행은 확인하지 않았다.
