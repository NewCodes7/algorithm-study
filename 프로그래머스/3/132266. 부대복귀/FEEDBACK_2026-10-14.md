## 1. 빠른 복습 — 다음 문제를 풀기 전 기억할 것

1. **출발지는 여러 개, 목적지는 하나**라면 출발지마다 BFS를 반복하기 전에 **목적지에서 BFS 한 번**으로 결과를 모두 구할 수 있는지 생각하기.
2. 이 문제는 **양방향 도로·간선 비용 1**이므로 `dist(A,B) = dist(B,A)`. 목적지에서 역방향 BFS를 해도 각 출발지의 복귀 최단거리가 됨. 방향 그래프라면 역방향 간선을 따로 구성해야 함.
3. **BFS 한 번은 O(V+E)**이지만, 각 노드에서 `sources`를 다시 전부 훑으면 O(VS)가 추가됨. 반복문 개수보다 **전체 실행 횟수**로 복잡도 계산하기.
4. 여러 조회에 공통인 정보를 `dist[]`에 **한 번 전처리**하고, 답은 인덱스로 O(1)에 조회하기.
5. `Arrays.fill(dist, -1)`로 초기화하면 도달 불가능(-1)과 미방문 상태를 함께 표현 가능. 방문 시 `dist[next] = dist[curr] + 1`.
6. `Queue<Integer> q = new ArrayDeque<>()`를 사용하면 `Integer[]` 객체에 노드와 거리를 함께 넣을 필요가 없음.
7. 최종 의사코드를 만든 **이후에도**, 구현 전에 반복문 내부의 비용이 제한에 맞는지 재검토하기.

| 회고할 장면 | 다음부터 취할 행동 |
| --- | --- |
| 첫 풀이가 출발지마다 BFS | 출발지·목적지 중 어디가 공통인지 확인하고 탐색 방향 결정 |
| 재풀이에서 BFS 내부에 sources 반복문 | 거리 계산과 결과 조회 분리 |
| visited와 단계 배열을 따로 관리 | dist=-1을 미방문 표식으로 이용 |
| Integer[]를 큐에 삽입 | 정수만 넣고 dist[]에서 거리 관리 |

## 2. 첫 풀이 (18분): sources마다 BFS

인접 리스트 구성, 방문 시점을 큐 삽입 순간으로 둔 점, 도달 불가능하면 -1을 반환한 점은 올바름.

다만 `for (int i = 0; i < sources.length; i++) answer[i] = bfs(...)` 형태로 동일한 그래프를 출발지 수만큼 다시 탐색함.

- `V = n` (정점 수)
- `E = roads.length` (무방향 간선 수)
- `S = sources.length` (답을 구할 출발지 수)

인접 리스트 구성 O(V+E), BFS 한 번 O(V+E), S번 실행 O(S(V+E)).
따라서 최초 코드 전체는 **O(S(V+E))**. BFS 한 번의 시간복잡도 O(V+E)를 전체 코드에 그대로 적용할 수 없음.

참고: 최초 코드의 `map`은 인스턴스 필드에 저장됨. 동일한 `Solution` 인스턴스에서 `solution()`을 재호출하면 이전 간선이 남으므로 지역 변수로 관리하는 편이 안전함. 프로그래머스의 일반적인 단일 호출 정답과는 별개인 코드 재사용성 문제임.

## 3. 재풀이 (11분): 역방향 BFS로 한 번만 탐색

`destination`에서 BFS를 시작해 여러 번 탐색하던 문제를 해결함. `visited[destination] = true`도 올바르게 초기화함. 모든 도로가 무방향·동일 비용이므로 큐에서 꺼낸 거리로 복귀 최단거리를 얻는 로직 자체는 맞음.

그러나 다음 코드가 BFS 안에 있음.

```java
for (int i = 0; i < sources.length; i++) {
    if (curr[0] == sources[i]) {
        answer[i] = curr[1];
    }
}
```

도달 가능한 정점을 R개 방문하면 매 정점마다 S회 비교하므로 O(RS), 최악 O(VS)가 추가됨.

- 그래프 구성: O(V+E)
- BFS 큐 처리 및 인접 정점 확인: O(V+E)
- 매번 전체 sources 대조: 최악 O(VS)
- 결과 배열 초기화: O(S)
- **재풀이 전체: O(V+E+VS)**

제한 최대치(정점 100,000개, 출발지 500개)에서는 출발지 비교가 최대 약 5,000만 회 발생할 수 있음. 첫 풀이보다는 탐색 중복이 줄었지만, 의도한 선형 시간에는 아직 도달하지 못함.

## 4. 개선 코드 (참고용) — 원본 Java 파일은 수정하지 않음

```java
import java.util.*;

class Solution {
    public int[] solution(int n, int[][] roads, int[] sources, int destination) {
        List<List<Integer>> map = new ArrayList<>();
        for (int i = 0; i <= n; i++) {
            map.add(new ArrayList<>());
        }
        for (int[] road : roads) {
            int x = road[0];
            int y = road[1];
            map.get(x).add(y);
            map.get(y).add(x);
        }

        // 목적지에서 모든 정점까지의 최단거리
        int[] dist = new int[n + 1];
        Arrays.fill(dist, -1);
        Queue<Integer> q = new ArrayDeque<>();
        q.offer(destination);
        dist[destination] = 0;

        while (!q.isEmpty()) {
            int curr = q.poll();
            for (int next : map.get(curr)) {
                if (dist[next] == -1) {
                    dist[next] = dist[curr] + 1;
                    q.offer(next);
                }
            }
        }

        // 결과 조회는 BFS 종료 후 한 번만
        int[] answer = new int[sources.length];
        for (int i = 0; i < sources.length; i++) {
            answer[i] = dist[sources[i]];
        }
        return answer;
    }
}
```

`dist[next] == -1`은 미방문 여부를 뜻하므로 별도의 `visited[]`가 없어도 됨. 이 문제에서 거리 0은 목적지 자신에게만 주어짐.

| 풀이 | 시간복잡도 | 추가 공간복잡도 |
| --- | --- | --- |
| 최초: 출발지별 BFS | O(S(V+E)) | O(V+E+S) |
| 재풀이: 목적지 BFS + 모든 sources 확인 | O(V+E+VS) | O(V+E+S) |
| 개선: 목적지 BFS + dist 배열 조회 | **O(V+E+S)** | O(V+E+S) |

여기서 공간복잡도에는 인접 리스트·방문 또는 거리 배열·큐·결과 배열이 포함됨. 평균적인 Java 컬렉션 구현의 객체 오버헤드는 점근적 표기에서 생략함.
