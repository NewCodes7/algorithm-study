## 꼭 기억할 핵심 피드백

1. **최단 경로에서 위치만이 상태인지 먼저 확인!** 같은 칸에 도착해도 진입 방향이 다르면 다음 칸에서 코너 비용 500원이 달라짐. 따라서 일반적인 2차원 score[x][y]의 최소값 하나로는 안전하게 가지치기할 수 없음. 정확한 상태는 **(행, 열, 진입 방향)**.
2. **96점 오답의 핵심:** 중간 버전의 if (score[nx][ny] >= newPath.cost)는 현재 비용이 높은 경로를 무조건 버림. 낮은 비용으로 도착했어도 다음 이동에서 꺾어야 하는 경로보다, 조금 더 비싸더라도 직진할 수 있는 경로가 최종 비용에서 유리할 수 있음. 동률을 허용하는 >= 만으로 해결할 수 없음.
3. **최종 버전의 500원 허용:** newPath.cost - 500 <= score[nx][ny]로 방향 차이를 간접 고려함. 이번 풀이에서 유효한 개선이지만, 같은 위치에 비용이 비슷한 **많은 경로를 큐에 계속 넣는 방식**이므로 메모리·시간 효율성이 낮음. 더 일반적이고 간결한 방법은 방향별 최솟값 4개를 저장하는 것.
4. **메모리 초과 원인:** 첫 시도는 매 상태마다 지나온 경로 전체를 복사해 경로 길이만큼 메모리 사용이 커짐. 변경한 Path 객체 연결 방식은 새 노드를 O(1)로 생성하지만, 수많은 후보 경로 객체·좌표 배열·큐 요소와 이전 노드 참조가 누적될 수 있음. 경로 자체는 정답에 필요하지 않음.
5. **contain()의 비용:** 현재 상태에서 이전 Path 객체를 따라가며 지나온 칸을 검사하므로 호출 1회가 경로 길이 L에 대해 O(L). 상태별 최소 비용으로 갱신하는 방식이면 이 역추적이 필요 없어짐.
6. **'깊은 복사' 주석 수정할 것:** Path(Path path)는 이전 객체 전체를 복사하지 않고 beforePath = path로 참조를 공유하는 **연결 리스트 형태의 경로 노드 생성**. 현재처럼 이전 노드를 수정하지 않으면 그 공유 자체는 문제없음.
7. **코너 계산은 성립:** 할아버지 노드와 현재 노드의 행과 열이 모두 다를 때 수직·수평 이동이 한 번씩 일어난 것이므로 방향이 꺾임. 다만 매 이동마다 두 단계 역추적하기보다는 직전 이동 방향을 저장하면 바로 비교 가능.
8. **메모리 제한:** 문제 공개 설명에 MB 값이 명시되어 있지 않아 실제 제한을 단정할 수 없음. 256MB/512MB 등의 수치를 사실처럼 기록하지 않기. 객체 수 증가만으로도 어떤 고정 제한에서든 메모리 초과가 날 수 있음.

## 향후 해볼 풀이 (사용자가 아직 작성한 코드 아님)

**1순위 — 3차원 최솟값 배열 + 큐 기반 완화**
- dist[x][y][dir]에 각 좌표로 해당 방향에서 진입했을 때 최솟값 보관.
- 다음 이동 방향이 같으면 +100원, 다르면 +600원.
- 더 싼 비용으로 갱신된 상태만 큐에 추가. 이전 경로 리스트·contain() 제거.
- 개선 없이 남아 있던 큐 원소는 꺼냈을 때 dist와 비교해 건너뛸 수 있음(비용·방향을 함께 큐에 저장).
- 격자 최대 25×25일 때 25×25×4개 int 배열은 약 10KB (배열 객체 오버헤드 제외).

**2순위 — 다익스트라**
- 움직임마다 100원 또는 600원이 들어가는 양의 가중치 그래프. PriorityQueue로 현재 누적 비용이 가장 작은 (x, y, dir) 상태부터 탐색.
- 네 방향 상태 수 O(N²), 연결 간선도 O(N²)이므로 일반적인 시간 O(N² log N), 최솟값 배열 O(N²). 우선순위 큐의 중복 엔트리는 추가 메모리가 필요할 수 있음.

## 재풀이 목표

- 힌트 없이 **왜 방향이 상태에 포함되어야 하는지** 설명하고 dist[행][열][방향]으로 다시 구현.
- 경로 역추적 없이 코너 비용을 계산하고, 더 높은 비용의 같은 상태를 안전하게 버리는 조건 증명.
- 이후 같은 문제를 PriorityQueue 다익스트라로 구현해 BFS식 비용 갱신과 비교하기.
