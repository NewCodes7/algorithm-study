- 코드: [택배상자.java](./택배상자.java) — **최초 작성한 코드와 주석을 유지**. 아래 개선 코드는 참고용이며 원본 파일을 대체하지 않음.

## 잘한 점: 필요한 상태만 관리함

1. **메인 컨베이어는 반복문 변수 `i` 하나로 표현.** 1부터 n까지 상자가 들어오므로 별도 큐나 배열을 만들지 않아도 됨.
2. **보조 컨테이너는 LIFO이므로 스택 사용.** 쌓아 둔 상자를 가장 최근 것부터 확인하는 `peek()`와 `pop()`이 문제의 제약에 맞음.
3. **`depth` 하나로 다음 목표와 정답을 동시에 관리.** `order[depth]`가 다음 적재 목표이고, `depth`가 지금까지 트럭에 적재한 개수임.
4. **`while`로 연속 적재.** 메인 컨베이어의 상자 하나를 적재한 직후 보조 컨테이너에서 다음 목표와 맞는 상자가 연속해서 나올 수 있으므로 `if`가 아니라 `while`이 필요함.
5. **`!stack.isEmpty()`를 먼저 확인.** `&&`의 단락 평가(short-circuit)로 빈 스택에 `peek()`하는 상황을 방지함.

## 경계 조건과 리팩토링 포인트

### 1. `order[depth]` 범위는 왜 원본에서 안전한가?

원본:
```java
while (!stack.isEmpty() && stack.peek() == order[depth]) {
    stack.pop();
    depth++;
}
```

- `depth == n`이라면 주문된 모든 상자를 이미 적재한 상태임.
- 이 문제의 `order`는 1부터 n까지 각 상자가 **정확히 한 번** 등장하므로, 모든 상자를 실었다면 보조 컨테이너도 비어 있음.
- 그러므로 `!stack.isEmpty()`가 `false`가 되어 `order[n]`에 접근하지 않음. 바깥 `for`에서도 모든 상자를 실은 뒤 다음 회차로 넘어갈 수 없음.
- **즉 원본도 문제 조건에서 정상 작동**함. 다만 범위 의존성을 줄이고 의도를 명확하게 하려면 `depth < n`을 명시하는 편이 읽기 쉬움.

```java
while (depth < n && !stack.isEmpty()
        && stack.peek() == order[depth]) {
    stack.pop();
    depth++;
}
```

### 2. `continue`는 제거 가능

원본의 `else`에서는 `i != order[depth]`일 때 `stack.push(i)`한 다음 `continue`함.
`continue`를 빼도 방금 넣은 상자가 스택의 맨 위이고 `i != order[depth]`이므로 뒤의 `while`은 즉시 종료됨. **동작은 같음.**
현재처럼 `continue`를 남겨도 논리 흐름은 명확하니 취향·가독성에 따라 선택해도 됨.

### 3. `Stack`보다 `ArrayDeque`를 기본 선택으로

- `Stack`은 오래된 `Vector`를 상속하며 주요 조작에 동기화가 적용됨. 코딩테스트의 일반적인 단일 스레드 실행에서는 불필요한 동기화 비용이 있을 수 있음.
- `ArrayDeque`는 배열 기반이고 기본적으로 동기화하지 않음. `Stack`처럼 `push()`, `pop()`, `peek()`를 그대로 사용 가능함.
- `Stack`은 `Vector`를 상속하므로 `get(index)` 등 스택 규칙 밖의 임의 위치 접근도 가능하지만, `Deque`는 양 끝에서의 조작을 위한 인터페이스임.
- **둘 다 스택으로 쓸 때 `push/pop`은 분할상환 O(1).** 실제 성능 차이는 입력과 JVM에 따라 다르므로 무조건 더 빠르다고 단정하지 않기.
- `ArrayDeque`는 `null` 저장 불가, 동시 접근을 위한 스레드 안전성도 제공하지 않음. 이 문제에서는 문제 되지 않음.

외워 둘 선언 및 연산:
```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(10);
stack.peek();     // 10, 제거하지 않음
stack.pop();      // 10, 제거함

Queue<Integer> queue = new ArrayDeque<>();
queue.offer(10);  // 큐 뒤에 추가
queue.poll();     // 큐 앞에서 제거
```

## 참고: 원본을 최소한으로 다듬은 버전

```java
import java.util.*;

class Solution {
    public int solution(int[] order) {
        Deque<Integer> stack = new ArrayDeque<>();
        int n = order.length;
        int depth = 0;

        for (int i = 1; i <= n; i++) {
            if (i == order[depth]) {
                depth++;
            } else {
                stack.push(i);
            }

            while (depth < n && !stack.isEmpty()
                    && stack.peek() == order[depth]) {
                stack.pop();
                depth++;
            }
        }

        return depth;
    }
}
```

**중요:** 학습 기록에서는 사용자의 최초 풀이와 개선안을 구분한다. 최초 풀이를 사후에 수정하여 원래부터 이렇게 풀었던 것처럼 만들지 않기.

## 복잡도

- **시간 O(N):** 바깥 `for`가 N회 실행됨. 중첩된 `while`도 각 상자가 스택에 최대 한 번 들어가고 최대 한 번 나오므로 모든 회차를 통틀어 최대 N회 `pop()`함. 중첩 반복문이라고 곧바로 O(N²)으로 계산하면 안 됨.
- **공간 O(N):** 최악의 경우 보조 컨테이너에 N-1개의 상자가 쌓임.
