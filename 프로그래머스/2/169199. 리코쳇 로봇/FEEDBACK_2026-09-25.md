## 1. 빠른 복습

문제 내용을 몰라도 다음 풀이에 적용할 수 있는 습관부터 정리함.

- BFS 초기화는 큐 생성, 방문 배열 생성, 시작점 삽입, 시작점 방문 처리를 한 묶음으로 기억하기.
- 방문 처리는 큐에서 꺼낼 때가 아니라 큐에 넣는 순간 하기.
- 실패하는 경우를 전부 나열해 분기하기보다, 알고리즘이 끝날 때 답을 못 찾은 경우를 처리하기.
- 구현 전에 상태, 한 번의 이동, 방문 기준, 성공·실패 반환값을 정하기.
- BFS 복잡도는 방문 상태 수뿐 아니라 각 상태에서 다음 상태를 구하는 비용까지 포함하기.
- 시작점 방문 표시 누락이 실제로 어떤 영향을 주는지 구분하기. 이 코드에서는 시작점 중복 처리가 생길 수 있지만 그 자체로 무한 루프가 생기지는 않음.

| 주제 | 기억할 내용 |
| --- | --- |
| BFS 초기화 | queue, visited, 시작점 삽입, 시작점 방문 처리 |
| 방문 시점 | 큐에 넣는 순간 표시 |
| 실패 처리 | 목표를 찾지 못한 채 큐가 비면 -1 |
| 분기 설계 | 일반 탐색으로 처리되는 상황에 별도 예외 분기를 붙이지 않기 |
| 복잡도 | 상태 수 × 상태마다 다음 위치를 구하는 비용 |
| Java 큐 | 단순 BFS에는 Queue<int[]> q = new ArrayDeque<>() 사용 가능 |

## 2. 전체 평가: BFS의 상태와 간선을 정확히 잡았음

최종 코드는 문제 조건에 맞는 BFS 풀이이며, 정적 검토상 잘못된 로직은 보이지 않음.

| BFS 요소 | 이 문제에서의 의미 |
| --- | --- |
| 상태 | 로봇이 멈춰 있는 위치 |
| 간선 하나 | 한 방향으로 끝까지 미끄러지기 |
| 거리 | 미끄러진 횟수 |
| 방문 처리 | 해당 위치에 최소 횟수로 도달했음 |

멈춘 위치만 큐에 넣고 이동 횟수를 +1 하는 것이 핵심임. 여러 칸을 지나더라도 한 번 미끄러지는 동작의 비용은 1이므로 BFS로 최소 이동 횟수를 구할 수 있음.

같은 위치에 도착했다면 어느 방향에서 왔든 다음에 할 수 있는 행동이 같음. 따라서 도착 방향을 상태에 포함하지 않고 visited[x][y]만 사용해도 충분함.

이동 중간에 G를 지나치는 것은 성공이 아님. 멈춘 위치를 큐에서 꺼낸 뒤 목표인지 확인하는 현재 구현이 정확함.

## 3. 회고 보완: 예외를 전부 나열하기보다 실패도 처리하는 구조 만들기

원래 회고:

> 도달할 수 없는 경우의 수가 생각보다 더 있었음. 예외 상황 제대로 꼼꼼하게, 경우의 수 최대한 꼼꼼하게 생각해보고 들어가자.

경계 상황을 꼼꼼하게 확인하는 태도는 필요함. 다만 구현을 개선하는 행동은 다음처럼 구체화하는 편이 좋음.

> 경계 상황은 확인하되, 실패하는 경우를 전부 나열해서 분기 처리하려 하지 말자. 탐색을 끝내도 답을 찾지 못한 경우의 반환값부터 정하자.

코드에 직접 남긴 다음 판단이 정확함.

> 애초에 위 체크 없었어도 됨. BFS 어차피 완전탐색하고 while 종료될테니 그 때에도 answer 갱신 없으면 -1 반환하면 되는 구조임

도달할 수 없는 이유는 다양함.

- 목표에서 멈출 수 없음.
- 목표가 장애물에 둘러싸여 있음.
- 목표에서 멈출 수 있는 구조이지만 출발점에서 접근할 경로가 없음.

각 이유를 따로 판별할 필요는 없음. BFS가 도달 가능한 위치를 모두 확인했는데 목표가 없었다면 모든 도달 불가능 상황을 한꺼번에 처리한 것임.

### 주석 처리한 사전 검사는 틀렸나?

현재 주석 처리된 검사 자체는 틀린 검사가 아니라 없어도 되는 검사임.

- 내부에 있는 G의 상하좌우가 모두 빈칸이면 그 위치에서 멈출 수 없다는 판단은 맞음.
- R이 있는 칸도 통과 가능한 칸이므로 map에서 0으로 둔 처리와 모순되지 않음.
- G가 가장자리에 있거나 장애물과 인접하는 것은 도달 가능성을 위한 필요조건임.
- 이 조건을 만족한다고 실제로 도달할 수 있다고 보장되지는 않음.
- 전체 도달 가능성은 BFS가 판단하므로 사전 검사를 생략해도 됨.

## 4. BFS 초기화와 방문 처리

원래 회고의 다음 항목은 그대로 가져가면 됨.

> bfs 처음에 세팅해야 하는 것 - queue, visited, 초기원소삽입, 초기원소방문체크

```java
Queue<int[]> q = new ArrayDeque<>();
boolean[][] visited = new boolean[n][m];

q.offer(new int[] {robotX, robotY, 0});
visited[robotX][robotY] = true;
```

핵심 규칙은 “큐에 넣는 순간 방문 처리한다”임. 시작점과 이후에 발견하는 위치에 같은 규칙을 적용함.

```java
if (!visited[nx][ny]) {
    q.offer(new int[] {nx, ny, pos[2] + 1});
    visited[nx][ny] = true;
}
```

### 시작점 방문 처리를 빠뜨렸을 때의 실제 영향

이 코드에서 시작점 방문 처리를 빠뜨렸다고 바로 오답이나 무한 루프가 발생하는 것은 아님.

시작점이 다시 큐에 들어가 한 번 더 처리될 수 있지만, 그때는 위 분기에서 방문 처리되므로 계속 반복되지는 않음. 시작점은 이미 이동 횟수 0으로 처리되었으므로 이후 중복 처리가 최단 경로를 더 좋게 만들지도 않음.

시작점을 미리 방문 표시하면 모든 상태를 한 번만 큐에 넣는 규칙이 유지됨. 장애물이나 경계가 바로 옆이라 전혀 움직이지 못하는 방향도 제자리의 방문 검사로 자연스럽게 제외됨.

최초 코드와 실패 입력 전체는 제공되지 않았으므로, 처음 실패한 테스트 4개의 원인을 시작점 방문 누락으로 단정하지 않음.

## 5. 성공·실패 반환 흐름 단순화

현재 answer = -1을 기본값으로 두고 성공할 때 갱신하는 코드도 맞음. 아래처럼 성공하면 즉시 반환하고 탐색이 끝나면 실패를 반환하면 더 명확함.

```java
while (!q.isEmpty()) {
    int[] pos = q.poll();

    if (map[pos[0]][pos[1]] == 2) {
        return pos[2];
    }

    // 기존 이동 및 방문 처리
}

return -1;
```

answer 변수와 break가 필요 없어짐.

- 성공: 목표 위치 발견.
- 실패: 목표를 찾지 못한 채 큐 소진.

정답의 기본값을 0으로 놓으면 도달하지 못한 경우에도 0을 반환할 수 있음. 문제에서 요구하는 실패 반환값을 먼저 확인하고 코드에 반영하기.

## 6. 시간·공간 복잡도

n은 행 수, m은 열 수.

“BFS니까 O(nm)”으로 끝내지 말고 각 위치에서 다음 위치를 찾는 비용까지 계산해야 함.

| 항목 | 비용 |
| --- | --- |
| 입력을 2차원 배열로 변환 | O(nm) |
| 방문 가능한 위치 수 | 최대 nm개 |
| 위치 하나에서 상하로 미끄러지는 탐색 | 합쳐서 O(n) |
| 위치 하나에서 좌우로 미끄러지는 탐색 | 합쳐서 O(m) |
| 전체 시간 | O(nm(n + m)) |
| map, visited, 큐의 추가 공간 | O(nm) |

가로·세로가 각각 최대 100임. 단순하게 크게 잡아도 10,000개 위치 × 4방향 × 100칸으로 약 400만 번의 이동 검사 수준임. 모든 칸에 실제로 멈출 수 있다고 잡은 보수적인 상한이며, 이 문제에서는 현재 구현으로 충분함.

## 7. 선택적인 Java 구현 개선

알고리즘을 바꾸거나 과하게 최적화할 필요는 없음.

| 현재 코드 | 개선 방향 |
| --- | --- |
| new LinkedList<>() | 단순 BFS 큐에는 new ArrayDeque<>()를 기본으로 사용 |
| robotX, robotY | 행·열 의미를 드러내려면 robotRow, robotCol 사용 |
| int[][] map의 1, 2 | char[][]로 'D', 'G'를 유지하면 숫자의 의미를 따로 기억할 필요가 없음 |

문자 배열을 유지하는 경우 다음처럼 바꿀 수 있음.

```java
char[][] map = new char[n][];
for (int row = 0; row < n; row++) {
    map[row] = board[row].toCharArray();
}
```

이후 장애물은 map[row][col] == 'D', 목표는 map[row][col] == 'G'로 검사함. 현재 정수 배열 방식도 정답에는 문제가 없으며, 위 제안은 가독성을 위한 선택임.
