## 1. 빠른 복습

- **후보의 범위**를 먼저 정의하기. 비밀 코드는 `1..n`에서 서로 다른 5개를 뽑음. `q`는 그 후보가 조건에 맞는지 검증하는 자료이며 후보의 원소를 제한하지 않음.
- 재귀로 조합을 만들 때 다음 시작값은 `i + 1`. `depth + 1`을 쓰면 선택한 값과 관계없이 다음 탐색을 시작해 중복·잘못된 조합이 생김.
- 후보를 증가하는 순서로 생성하면 같은 5개 조합은 한 번만 나오고 이미 정렬되어 있음. `Set`, 정렬, 문자열 키 만들기 없이 맞는 조합마다 답을 1 증가시키기.
- `this.ans = ans`처럼 매개변수와 필드가 같은 이름일 때 `this`로 필드를 명시하기.
- `Arrays.sort(int[])`도 오름차순 정렬 가능. **비교 함수가 있는 `Arrays.sort(array, comparator)`에는 `Integer[]` 같은 참조형 배열**을 사용해야 함.
- 객체 필드는 호출 사이에 상태가 남음. `Solution` 인스턴스를 재사용한다면 결과 카운터나 집합을 `solution()` 시작 시 초기화하기.

| 질문 | 이번에 적용할 규칙 |
| --- | --- |
| 무엇을 생성하나? | `1..n`에서 5개 조합 |
| `q`의 역할은? | 생성한 후보와 교집합 크기가 `ans[i]`인지 검사 |
| 어디서 중복을 막나? | 재귀에서 `i + 1`부터 선택하는 순간 |
| 최대 경우의 수는? | `C(30, 5) = 142,506` |

## 2. 정답 판단과 설계에서 놓쳤던 것

현재 최종 코드는 `1..n`의 오름차순 5개 조합을 생성하고 각 질문과 일치하는지 확인하므로, **일반적인 단일 호출에서 문제 조건에 맞는 답을 계산함**.

초기 구상처럼 각 `q`에서만 숫자를 골랐다면 답을 누락함. 실제 문제의 두 번째 예시에서 가능한 조합 5개 모두에 숫자 `5`가 있는데, 모든 `q`를 합쳐도 `5`는 없음. 질문에 등장한 숫자와 정답 후보의 범위는 서로 다른 개념임.

다음 문제에서는 구현 전 세 문장을 적어보기.

1. 정답 후보를 이루는 원소의 전체 범위는 무엇인가?
2. 입력 중에서 후보를 정의하는 것과 후보를 검사하는 것은 무엇인가?
3. 후보가 작은 예시에서 빠지지 않았는가? 예를 들어 `n=10`, `q=[[1,2,3,4,5]]`, `ans=[0]`이면 `[6,7,8,9,10]`도 가능함.

예시를 따라 실행하며 가설을 확인하되, 전체 범위는 문제 문장으로 먼저 확정하기. 코드를 쓰기 전에 이 세 문장을 검토하면 `q` 내부에서 조합을 만드는 시행착오를 줄일 수 있음.

## 3. 코드에서 단순화할 곳

- `idx`, `cnt`는 재귀 인자로 전달되지만 읽지 않음. `check`의 `idx`도 사용하지 않음.
- 현재 `depth`는 재귀 깊이가 아니라 **다음에 고를 수 있는 최소 숫자**임. `next`나 `start`로 이름을 바꾸면 `i + 1`이 자연스럽게 읽힘.
- 재귀가 매번 `i + 1`로 진행하므로 같은 조합은 한 번만 생성되고 `curr`도 오름차순임. `Integer[] temp` 복사, 정렬, `StringBuilder`, `Set`을 제거해도 됨.
- 기존 `set`이 필드에서 처음 한 번만 만들어짐. 같은 인스턴스에서 `solution()`을 여러 번 호출하면 이전 결과가 섞임. 카운터를 필드로 두더라도 각 호출에서 `answer = 0`으로 초기화하기.
- `Stack.contains`는 최대 5개 중에서 찾으므로 이 제한에서는 충분함. 더 단순한 조회 비용이 필요하면 `boolean[n+1]`에 현재 조합의 숫자를 표시한 뒤 `chosen[number]`로 검사 가능.

### 원래 구조를 유지해 정리한 코드

```java
import java.util.*;

class Solution {
    private int n;
    private int[][] q;
    private int[] ans;
    private int answer;

    public int solution(int n, int[][] q, int[] ans) {
        this.n = n;
        this.q = q;
        this.ans = ans;
        this.answer = 0;

        combination(new Stack<>(), 1);
        return answer;
    }

    private void combination(Stack<Integer> curr, int next) {
        if (curr.size() == 5) {
            if (matchesAll(curr)) answer++;
            return;
        }

        for (int i = next; i <= n; i++) {
            curr.push(i);
            combination(curr, i + 1);
            curr.pop();
        }
    }

    private boolean matchesAll(Stack<Integer> curr) {
        for (int i = 0; i < q.length; i++) {
            int count = 0;
            for (int number : q[i]) {
                if (curr.contains(number)) count++;
            }
            if (count != ans[i]) return false;
        }
        return true;
    }
}
```

원본 Java 파일을 대체하는 코드가 아니라, 불필요한 자료구조를 덜어 낸 복습용 제안임.

## 4. 시간·공간 복잡도

문제 제한은 `n <= 30`, `m = q.length <= 10`, 각 `q[i]`의 길이는 5임. 가능한 후보 수 `C(n, 5)`의 최댓값은 `C(30, 5) = 142,506`.

원본의 `Stack.contains`는 최악에 5개를 확인함. 후보 하나의 검증은 최악 `m × 5 × 5`회의 비교로 볼 수 있으므로 전체 시간 상한은 대략 `O(C(n,5) × m × 25)`이며, 이를 `10^10`가지 후보로 계산할 필요는 없음. 개선 코드도 동일한 조합을 생성하고 같은 방식으로 검증함.

개선 코드의 추가 공간은 재귀 깊이·현재 조합에 쓰는 `O(5)`임. 원본은 정답을 문자열로 만들어 `Set`에 저장하므로 유효한 조합 수에 비례한 메모리를 추가로 사용함.

## 5. Java 문법 메모 수정

```java
int[] values = {3, 1, 2};
Arrays.sort(values); // 가능: 오름차순

Integer[] boxed = {3, 1, 2};
Arrays.sort(boxed, (a, b) -> Integer.compare(a, b)); // 비교 함수를 전달하려면 참조형 배열
```

원본의 `// int라 하면 Arrays.sort 안 됨`은 `int[]` 자체가 아니라 **`int[]`에 비교 함수를 전달할 수 없음**으로 고쳐 기억하기. 원본의 `Stack.get(i)`는 가능함. `Stack`이 `Vector`를 상속하기 때문임.
