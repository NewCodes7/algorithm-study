# 충돌위험 찾기 피드백 — 2026-09-24

## 복습 요약

- 배열 대입은 값 복사가 아니라 참조 공유다. 수정할 배열이 원본이나 다른 객체와 공유되어도 되는지 먼저 판단한다.
- Arrays.copyOf(원본, 새 배열 길이)로 복사한다. 두 번째 인자는 새 배열의 길이다.
- 종료 조건의 변수가 인덱스인지 개수인지 구분한다. 한 반복에서 여러 개가 증가하면 특정 값을 건너뛸 수 있다.
- int[][] arr = new int[n][]도 가능하다. 다만 각 행이 null이므로 arr[i][0] 접근 전에 행 배열을 할당해야 한다.
- 시뮬레이션은 한 반복이 나타내는 시각과 충돌 확인·도착 처리·이동 순서를 먼저 정한다.

4. 2차원 배열 생성 이렇게도 가능 int[][] robotsTo = new int[routes.length][];

## 디버깅에서 배운 점

### 1. from이 여러 칸 이동하는 것처럼 보인 원인

초안의 robotsFrom[i] = points[pointFrom - 1]은 동일한 int[]를 가리킨다.
같은 지점에서 출발한 로봇들이 한 행 배열을 공유하면, 한 로봇을 이동시킨 변경이 다른 로봇에도 보인다.
반복문에서 다음 로봇까지 이동시키면 같은 배열이 또 변경된다.
robotsTo도 points를 참조하므로 원본을 바꾸면 목적지 좌표까지 바뀔 수 있다.

현재 위치 초기화에 Arrays.copyOf(points[pointFrom - 1], 2)를 사용해 해결했다.
목적지는 읽기만 하므로 현재 위치가 독립적으로 복사되어 있고 points를 수정하지 않는다면 참조 공유해도 된다.
현재처럼 목적지까지 복사해도 틀리지 않는다.

### 2. 무한루프의 원인

end는 종료된 로봇의 개수다. 따라서 전체 종료는 end == routes.length다.
초안의 end == routes.length - 1은 아직 한 대가 남았는데 종료할 수도 있다.
또한 같은 반복에서 여러 로봇이 종료하면 해당 값을 건너뛰어 영원히 종료하지 않을 수도 있다.
예를 들어 로봇 두 대가 함께 끝나면 end가 0에서 2가 되어 end == 1을 만족하지 않는다.

### 3. 2차원 배열 생성

new int[n][]는 바깥 배열만 만들며 각 행은 null이다.
초기화 반복문에서 모든 행에 복사한 int[]를 대입하는 현재 구조에서는 사용할 수 있다.
new int[n][2]로 미리 만든 행 배열은 이후 대입 시 교체된다.

### 4. 지역 변수와 배열 참조

int[] to = robotsTo[i] 이후 robotsTo[i]에 새 배열을 대입해도 to는 이전 배열을 가리킨다.
현재 이동 코드가 robotsTo[i]를 직접 읽으므로 문제없다.
이동 코드를 to로 단순화하려면 목적지 갱신 후 지역 변수도 갱신해야 한다.

## 잘한 점과 선택적 개선

- 현재 시각 충돌 확인 → 도착 처리 → 한 칸 이동 순서가 일관된다.
- 출발 시각과 마지막 목적지 도착 시각의 충돌이 포함된다.
- 중간 목적지에서 다음 목적지로 진행할 때 불필요하게 한 턴 쉬지 않는다.
- setAlready로 같은 위치에 3대 이상 모여도 한 번만 센다.
- 운행 종료 처리 뒤 continue를 추가하면 종료된 로봇은 이동하지 않는다는 의도가 더 명확해진다. 현재는 좌표가 같아 이동 조건이 모두 거짓이므로 실제 이동은 발생하지 않는다.
- 이번 병목은 알고리즘 선택보다 참조 공유와 종료 조건이었다. 예상하지 못한 값 변경은 공유 참조를, 무한루프는 종료 변수의 의미와 증가 폭을 먼저 점검한다.
